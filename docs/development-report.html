Math Garden Development Report

Malcolm Ferguson
Math Practice Web Application Using AI Agents
October 20, 2026

Math Garden is an arithmetic practice application for children ages 7–12. It provides four arithmetic operations, configurable sessions, multiple-choice cards, self-reported results, mistake review and browser-local progress. Codex assisted with requirements, source, tests and release materials. All 46 core and interface tests passed, along with linting and the production build. The source and commit history are on GitHub, and the public Netlify deployment was checked in a browser.

Development approach

The work began by reading the assignment and reviewing the major prompts and debugging decisions in the supplied Cursor transcript. The example site was opened to inspect its home and practice-setup pages. This established the expected interaction model: select operations, choose one of four difficulty levels, and complete a fixed-length or continuous session.

The initial attachments did not contain the detailed specification or implementation checklist. An independent question engine was started from the assignment overview. When the missing files were supplied, their requirements were incorporated before the interface was implemented. The project changed from an initially planned static JavaScript interface to React and React Router, as the specification explicitly requires. JavaScript is used for executable source; a TypeScript file documents the shared data models.

The instructor's checklist was grouped into practical milestones: question generation and storage; practice cards and sessions; review and statistics; then testing and release preparation. This reduced repeated setup while retaining the original checklist for comparison. Separate local Git commits preserve the foundation, the React interface, and later testing and documentation changes.

Architecture and design

React Context holds application state. Pure functions handle question generation, constraints, statistics, mistake updates and persistence. React Router provides the required pages; statistics and settings load separately. Local storage keeps one versioned snapshot, so completed answers and the next card are written together. No account or backend is needed.

The interface uses a garden theme with readable arithmetic, large answer buttons, visible keyboard focus and supportive language. A selected answer can be changed until the card flips. The learner's right or wrong self-report determines the saved result, even if it differs from the selected answer. This follows the specification's self-assessment model.

Prompts and debugging

Prompting strategy

The initial request established both the action and the sources: “Please review them, and complete the assignment. Let me know if there is any additional information you need.” Supplying the example-site link gave the agent a concrete reference for the required workflow. Providing the specification and checklist during development resolved missing information that materially changed the technology choice and review requirements.

The following short task directions summarize how the agent decomposed the work. They are useful follow-up prompts, rather than additional messages attributed to the student:

Implement configurable sessions with four answer choices, reveal the answer only after a choice is made, and use the learner's self-report for statistics. Save each result immediately and prevent duplicate recording.

Test all operation and difficulty combinations, related-question constraints, mastery transitions, corrupted storage and session recovery. Report separately which checks ran and which remain blocked.

These directions are effective because they describe observable behavior and acceptance criteria. They also prevent a common problem in AI-assisted development: interpreting generated source as proof that the application works.

Debugging experience

The agent's environment could not resolve package or Git hosts. The student installed dependencies and pushed commits using regular PowerShell. An initial npm command ran from Desktop and failed because package.json was in the project folder; changing to that folder resolved it. Vitest was later updated to 4.1.12, the tests passed again, and the student's fresh npm audit reported zero vulnerabilities.

The interface tests exposed a session-completion race: clearing the active session could trigger the missing-session redirect before navigation to the summary finished. The expected behavior was a summary after the fifth answer; the actual behavior returned to setup. An explicit completion flag corrected the redirect. The five-question integration test then passed, and a complete session on the public site verified the same behavior.

The reference transcript's disabled mistake-review button informed a regression check. Mistakes are updated when a wrong self-report is recorded. Both the automated integration test and a public-site session confirmed immediate review availability. Storage tests also verified that a corrupt data category does not discard valid categories.

Related question behavior

Review uses nearby operands, reversed addition or multiplication, and valid inverse fact families. Questions retain the original difficulty and respect selected operations. Repeated and recent mistakes with fewer successful reviews receive more weight. The mastery threshold defaults to three and can be changed in Settings. A new mistake resets the pattern's progress.

Testing and reflection

Completed verification

The dependency-free Node suite completed with 39 passing tests. Sixteen tests generate 1,000 questions each, covering all four operations at all four levels. They check arithmetic, operand constraints, integer answers, nonzero divisors, four unique choices and exactly one correct choice. Separate tests cover boundary values and constant random sources so generation cannot stall on duplicate distractors.

Related-question tests cover 1,600 examples, original-pattern links, difficulty constraints, reversed operands and inverse facts. State tests check self-report authority, duplicate-record prevention, immediate mistake creation, configurable mastery and resets after errors. Storage tests cover round-trip serialization, malformed JSON, unavailable or full storage, invalid categories and unusable active cards. A 5,000-attempt test checks aggregate accuracy and serialized size.

Seven React interface tests also passed. On the public site, five mixed questions with three right and two wrong self-reports produced 60% accuracy. Six successful related answers then mastered both missed facts. Statistics retained 11 attempts, 9 right answers and 82% rounded accuracy after refresh. The revealed card survived an active-session refresh, and Statistics and Settings supported direct-route refresh. Desktop views and a 390-pixel phone viewport were inspected. Cross-browser, screen-reader, audio and full keyboard-only checks remain unverified.

Reflection

This development process shows the value of an AI agent for connecting requirements to implementation and generating repeatable checks. The agent could organize related requirements, build a modular implementation and test thousands of cases quickly. Receiving the detailed specification also demonstrated why an agent should identify missing inputs early: an assumption about the frontend stack had to change once the authoritative requirements arrived.

The main limitation was the gap between writing code and verifying the complete product. Passing arithmetic tests cannot prove accessibility, usability, routing or deployment. The tooling failure also showed that an agent's progress depends on its execution environment. Useful collaboration requires clear status reporting, small reproducible checks and human review of the final behavior.

The student should review the reflection in their own voice and be able to explain the component flow, persistence model and mastery rules. Further personal observations can extend the recorded checks. The instructor's example transcript remains reference material; the separate evidence document records this project's actual interactions.
